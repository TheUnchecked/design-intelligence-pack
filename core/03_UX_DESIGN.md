# Design Intelligence Pack — UX Design

## Purpose

Define principles for designing digital experiences that are clear, usable, predictable and aligned with user goals.

UX decisions must prioritize user outcomes over visual novelty.

---

## 1. User Goal

Every interface should have a clear primary user goal.

Determine:

- who the user is;
- what they want to accomplish;
- why they are doing it;
- what information they need;
- what could prevent success.

### Rule

Do not optimize an interface for features. Optimize it for user outcomes.

---

## 2. Information Architecture

Organize information according to user needs and mental models.

Consider:

- hierarchy;
- grouping;
- navigation;
- labeling;
- relationships;
- discoverability.

### Avoid

- unnecessary navigation levels;
- ambiguous labels;
- duplicated content;
- inconsistent terminology;
- organization based only on internal business structure.

---

## 3. User Flow

A user flow should minimize unnecessary cognitive and interaction effort.

For important tasks:

1. Identify the starting point.
2. Define the desired outcome.
3. Identify required actions.
4. Remove unnecessary steps.
5. Identify possible failure points.
6. Provide appropriate feedback.

### Rule

Every step must have a purpose.

---

## 4. Interaction

Interactions should be:

- predictable;
- discoverable;
- consistent;
- responsive;
- reversible when appropriate.

Users should understand:

- what is interactive;
- what will happen;
- whether an action succeeded;
- how to recover from errors.

---

## 5. Affordance

Interactive elements should visually communicate their function.

Examples:

- buttons should look actionable;
- links should look like links;
- inputs should look editable;
- menus should indicate availability;
- disabled elements should communicate their state.

Avoid relying on hidden interaction patterns unless there is a strong reason.

---

## 6. Feedback

Every meaningful user action should produce appropriate feedback.

Feedback may communicate:

- success;
- failure;
- progress;
- loading;
- state change;
- completion.

### Rule

Never leave the user uncertain about whether an important action occurred.

---

## 7. Forms

Forms should minimize friction.

Consider:

- number of fields;
- field order;
- labels;
- defaults;
- validation;
- error messages;
- keyboard behavior;
- mobile interaction.

### Rules

- Ask only for necessary information.
- Use clear labels.
- Validate close to the point of error.
- Preserve user input after errors.
- Explain how to correct invalid data.

---

## 8. Error Handling

Errors are part of the experience.

An effective error state should explain:

1. What happened.
2. Why it happened when useful.
3. What the user can do next.

### Avoid

- technical error messages;
- blame-oriented language;
- unexplained failure;
- destructive recovery paths;
- clearing user input unnecessarily.

---

## 9. Empty States

An empty state should explain the situation and, when appropriate, provide a useful next action.

Consider:

- what is empty;
- why it is empty;
- what the user can do;
- whether an action is available.

Avoid decorative empty states that provide no useful information.

---

## 10. Navigation

Navigation should reflect the user's mental model.

### Rules

- Use familiar terminology.
- Keep important destinations discoverable.
- Maintain consistent navigation patterns.
- Make the current location understandable.
- Avoid unnecessary navigation complexity.

---

## 11. Calls to Action

A primary CTA should represent the most important desired action.

### Rules

- Make the primary action identifiable.
- Use clear action-oriented language.
- Avoid competing primary CTAs.
- Place actions where users expect them.

### Avoid

- vague labels;
- multiple visually dominant actions;
- manipulative urgency;
- hiding important actions.

---

## 12. Cognitive Load

Reduce unnecessary cognitive effort.

Consider:

- number of choices;
- information density;
- unfamiliar terminology;
- memory requirements;
- visual complexity;
- interaction complexity.

### Rule

Do not make users remember information that can reasonably remain visible.

---

## 13. Consistency

Similar problems should have similar solutions.

Maintain consistency across:

- terminology;
- navigation;
- controls;
- states;
- interactions;
- feedback;
- visual patterns.

Consistency reduces learning effort.

---

## 14. Accessibility

UX must account for different abilities and interaction methods.

Consider:

- keyboard navigation;
- screen readers;
- focus management;
- target sizes;
- contrast;
- readable content;
- reduced motion;
- cognitive accessibility.

Accessibility should influence the design from the beginning.

---

## 15. Responsive UX

Responsive design includes interaction behavior, not only visual dimensions.

Consider changes in:

- navigation;
- content priority;
- interaction method;
- touch targets;
- forms;
- tables;
- menus;
- information density.

---

## 16. UX Validation

Before considering an experience complete, ask:

### Goal
Can the user accomplish the primary task?

### Clarity
Does the interface communicate what to do?

### Discoverability
Can users find important functionality?

### Feedback
Do users understand system responses?

### Recovery
Can users recover from errors?

### Efficiency
Are unnecessary steps removed?

### Accessibility
Can different users interact successfully?

### Consistency
Does the experience behave predictably?

### Responsive Behavior
Does the experience remain usable across contexts?

---

## UX Principle

**The best interface is not the one with the most features. It is the one that helps the user achieve the intended outcome with the least unnecessary effort.**
