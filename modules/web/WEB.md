# Design Intelligence Pack — Web Module

## Purpose

Define how the Design Intelligence Master is applied to websites and web interfaces.

This module applies to:

- websites;
- landing pages;
- web applications;
- portals;
- dashboards;
- responsive interfaces.

---

## 1. Web Objective

Define:

- business objective;
- primary user goal;
- primary conversion or action;
- required content;
- success criteria.

---

## 2. Information Architecture

Define:

- pages;
- sections;
- navigation;
- content hierarchy;
- relationships between information.

The structure should reflect user needs rather than internal organizational structure.

---

## 3. User Flow

Identify:

- entry point;
- primary task;
- required interactions;
- conversion/action;
- completion state;
- possible failure points.

Remove unnecessary steps.

---

## 4. Page Structure

Each page should have an intentional hierarchy.

Typical elements may include:

- navigation;
- hero;
- supporting content;
- proof/evidence;
- benefits;
- functionality;
- calls to action;
- footer.

Do not treat this as a mandatory template.

Select sections according to the page objective.

---

## 5. Visual Hierarchy

Apply:

- typography;
- spacing;
- alignment;
- contrast;
- scale;
- position;
- color;

to establish clear information priority.

The primary message and action should be identifiable without excessive visual decoration.

---

## 6. Navigation

Navigation should be:

- predictable;
- consistent;
- discoverable;
- understandable.

Maintain clear indication of current location where appropriate.

---

## 7. Interaction

Interactive elements must communicate:

- that they are interactive;
- what action they perform;
- their current state;
- feedback after interaction.

Consider:

- hover;
- focus;
- active;
- disabled;
- loading;
- success;
- error states.

---

## 8. Responsive Design

Design for different contexts rather than simply shrinking desktop layouts.

Consider:

- mobile;
- tablet;
- desktop;
- viewport width;
- touch interaction;
- content priority;
- navigation;
- typography;
- images;
- forms;
- tables.

---

## 9. Accessibility

Consider:

- semantic HTML;
- heading hierarchy;
- keyboard navigation;
- focus management;
- accessible names;
- contrast;
- target sizes;
- reduced motion;
- screen-reader compatibility.

Do not rely on color alone to communicate meaning.

---

## 10. Performance

Consider:

- image optimization;
- unnecessary assets;
- excessive animation;
- rendering complexity;
- layout stability;
- loading experience.

Visual quality must not create unnecessary performance cost.

---

## 11. Content

Design around realistic content.

Test:

- long headings;
- long paragraphs;
- missing images;
- translated text;
- dynamic content;
- empty states;
- error states.

Do not design exclusively around placeholder content.

---

## 12. Conversion

For pages with a conversion objective:

Define:

- primary CTA;
- secondary actions;
- conversion path;
- friction points;
- trust signals.

Avoid competing primary actions.

---

## 13. Brand

When Brand Guidelines are available:

- use approved typography;
- use approved colors;
- respect imagery rules;
- maintain visual identity;
- preserve accessibility.

---

## 14. Web QA

Verify:

### Objective

Does the page support its intended business and user goal?

### UX

Can users complete the primary task?

### Hierarchy

Is the primary message clear?

### Responsive

Does the experience remain usable across viewport sizes?

### Accessibility

Can different users interact effectively?

### Performance

Are visual and interaction choices proportionate to their cost?

### Content

Does the layout survive realistic content?

### Consistency

Does the page follow the established design system?

### Anti-Patterns

Are unnecessary cards, gradients, animation, decorative elements or visual noise present?

---

## Web Principle

**A good web experience makes the intended action understandable, accessible and achievable with minimal unnecessary friction.**
